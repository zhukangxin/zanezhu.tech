## 引言：问题不在区块链，而在位置

跨境支付和稳定币平台的出路，不是全面放弃区块链，也不是继续把所有功能堆在链上，而是把区块链收缩为“信任的锚点”，把业务交给更擅长的系统。

过去几年，大量跨境支付企业和稳定币发行方把核心业务建在区块链上。现在它们遇到了同一个问题：单体链把共识、执行、存储、结算紧紧捆在一起，扩展性弱，功能迭代慢。

二层网络、侧链、状态通道缓解了吞吐压力，但没有解决根本矛盾。一个覆盖全球的支付平台，需要不断加入新的币种、新的通道、新的合规规则、新的产品形态。这种扩展速度，单体链架构跟不上。

于是，已经采用区块链的企业不得不思考下一步。业内常见三条路线：用分布式数据库重构平台；用分布式文件系统替换区块链；把区块链最小化，在其上增加多层能力。本文逐一分析它们的可行性和优劣，并给出一个判断标准。

核心论点只有一句：**区块链应该是信任的锚点，而不是业务的容器。** 更进一步，区块链的优势主要来自三项以自动化方式预设的能力：开放互操作、透明可审计、多方共同写入。在监管介入后，分布式数据库同样可以通过自动化协议预设这些能力，区块链的竞争力因此被严重削弱。

## 区块链真正不可替代的是什么

在评估任何替代方案之前，先要把区块链的能力拆开看。很多项目把“我们用了区块链”和“我们需要区块链”混为一谈。

| 能力 | 是否区块链独有 | 说明 |
| --- | --- | --- |
| 互不信任的多方共享一本账 | 名义上是 | 技术上由共识和密码学保证；实际信任取决于链的设计和运营企业 |
| 资产“持有即所有”，可自由流通 | 名义上是 | 链上记录可自由转移；记录与真实资产的对应取决于发行和运营企业 |
| 7×24 原子结算、结算即最终 | 部分 | 中心化系统也能做到，但跨机构做到很难 |
| 可编程（智能合约） | 否 | 传统系统也能实现，只是不那么开放 |
| 高吞吐、低延迟、海量存储 | 否，恰恰是弱项 | 这正是应该从链上移出去的部分 |
| 隐私、数据可修改与删除 | 否，与链的设计冲突 | 数据保护法规要求可删除，公链天然不可篡改 |

区块链在技术上提供的独特能力只有两件事——**多方信任**和**资产流通**，而且两者都只是名义上的保证，实际信任取决于链的设计和运营企业（详见下一节）。其余能力，数据库、消息系统和传统清算已经做了几十年，而且做得更好。

因此，评估一个平台应该怎么演进，关键问题是：**你的业务是否依赖这两件事？** 依赖的话，彻底替换区块链就会丢掉核心价值；不依赖的话，当初用区块链本身就可能是过度设计。

## 多方信任和资产流通，区块链到底能保证什么

区块链提供的是技术上可验证的信任，不是法律上可执行的信任；它保证的是一条链内的流通，不是跨系统、跨法域的流通。把这两点说清楚，才能判断监管介入后它还剩多少价值。

### 区块链为什么能提供多方信任

传统系统的信任来自“相信运营方”；区块链把它换成“相信密码学 + 相信多数参与方诚实”。具体靠四个机制：

1. **每方各持一份完整账本**：没有“唯一的主账本”，任何一方都不能单方面修改而不被其他方发现
2. **共识机制容忍作恶节点**：拜占庭容错共识在少数节点（通常不超过三分之一）作恶时仍能形成一致账本。普通分布式数据库只防崩溃，不防作恶
3. **数字签名决定所有权**：只有持有私钥的人能动用资产，运营方也无法代签
4. **哈希链使历史可检验**：改动任何一笔历史记录都会破坏后续所有区块的哈希，任何参与方都能独立重算验证

但这种信任是有条件的：它依赖多数验证者诚实、私钥安全、合约代码正确。更重要的是，**它只能保证链上数据的一致，保证不了链下事实的真实**。稳定币链上流通量是否真有等额美元资产存在银行里，区块链自己无法证明，只能靠审计和监管。

### 监管介入后，还需要区块链的多方信任吗

监管提供的是另一种信任：牌照、审计、资本要求、执法和追责。它是事后的、靠法律强制的；区块链的信任是事前的、实时可验证的。两者不是替代关系，但监管越强，区块链“代替信任”的作用越弱。

**在单一法域内，基本不需要。** 受监管的中心化系统（央行 RTGS、卡组织、国内快速支付系统）已经让互不信任的银行长期协作。这就是国内支付不需要区块链的原因。

**监管本身还在削弱“去信任”的叙事。** 美国《GENIUS 法案》要求支付稳定币发行方（包括在美国二级市场流通的外国发行方）保持冻结和销毁钱包的技术能力，以执行合法命令（[参议院银行委员会情况说明](https://banking.senate.gov/imo/media/doc/genius_fact_sheet_-_national_securitypdf.pdf)）。这种冻结能力覆盖与发行方没有业务关系的持有人，无论代币在托管钱包还是非托管钱包中（[Steptoe 分析](https://www.steptoe.com/en/news-publications/blockchain-blog/the-genius-act-and-financial-crimes-compliance-a-detailed-guide.html)）。也就是说，受监管稳定币的最终控制权在发行方和监管者手里，持有人信任的其实是发行方和法律，而不只是算法。

**在跨法域场景，仍有价值，但价值改变了。** 跨境支付中没有一个管得了所有参与方的监管者，各国也未必愿意把账本交给对方。这时一条由多方共同维护的结算层仍有意义。但它的作用已经从“替代信任”变成“降低验证和对账成本”：受监管机构之间共享一份可验证的事实记录，不必各自对账。而且这个作用并非区块链独有，一个中立的国际清算机构加上共同标准也能做到，电信的国际结算就是先例。

### 单靠区块链保证不了多方信任：谁来保证建设者不作恶

区块链方案能否保证信任，不仅取决于技术，还取决于建设者的**能力**和**意向**。单单一条区块链，保证不了多方信任。

同样的区块链技术，可以建成权力高度分散的系统，也可以建成完全由一家企业控制的系统。区别不在链，而在建设者：

- **能力**决定系统会不会“无意中失信”：密钥管理是否稳妥、合约是否经过审计、跨链桥是否安全、验证者是否真正独立。历史上金额最大的跨链桥被盗事件，多数是能力问题，不是区块链原理的问题
- **意向**决定系统会不会“有意地失信”：建设者是否保留管理员密钥、是否可以单方面升级合约规则、是否挑选由自己控制的验证者、是否挪用链下储备。这些都是写在系统设计里的权力，链会忠实执行，而不会阻止

区块链让**偷偷作恶**变难了：私改账本、伪造交易、篡改历史都会被所有节点发现。但它防不住**公开作恶**，因为那些操作本身就是系统授予建设者的权力。

| 谁可能作恶 | 作恶方式 | 区块链能否防住 |
| --- | --- | --- |
| 稳定币发行方 | 无储备超发；挪用储备；滥用冻结权 | 超发在链上可见，但储备在链下，链无法证明；冻结是合法功能 |
| 验证者 / 节点运营方 | 合谋审查交易；许可链节点集体改规则 | 节点越少、越集中，越难防 |
| 协议开发方 | 通过合约升级权限改变规则 | 防不住，代码就是这么写的 |
| Rollup 排序器 | 拒绝打包或操纵交易顺序 | 部分能防，取决于有无强制退出机制 |
| 跨链桥运营方 | 多签密钥被盗或合谋 | 防不住，历史上损失最大的环节 |
| 交易所 / 托管方 | 挪用客户资产（FTX 即是此类） | 完全无关，资产根本不在用户自己的链上地址 |

约束建设者，需要四层手段叠加：

1. **技术约束**：减少建设者手里的特权。验证者多元且独立；管理员权限加多签和时间锁，升级前给用户留出撤出时间；开源、审计、形式化验证
2. **经济约束**：质押罚没、声誉损失、用户可以转向竞争对手
3. **法律与监管约束**：牌照准入、储备要求、定期披露、独立审计、客户资产隔离。例如《GENIUS 法案》规定，发行方破产时稳定币持有人对储备享有优先求偿权（[Orrick 分析](https://www.orrick.com/en/insights/2025/07/stablecoin-framework-signed-into-law)）
4. **治理约束**：发行、出块、托管、开发由不同主体分别承担，互相制衡，不让一家企业同时握住所有钥匙

所以，约束受监管区块链企业不作恶的机制，和约束银行、清算所的机制基本相同。区块链的贡献是把建设者的行为变得**可见、可验证**，让监管和用户更容易发现问题，而不是让建设者无法作恶。**链是技术锚点，监管和法律是制度锚点，建设者的能力和意向决定两者能否落地。**

### 资产流通：系统转移的是信息，不是资金

**无论信息系统还是区块链，转移的都只是记录，不是资金本身。** 对法币稳定币来说，链上代币只是一条信息，代表持有人对发行方储备的求偿权。真正的美元一直存放在发行方的银行和托管账户里，并不随代币转移。

信息与资金是否一一对应，不取决于区块链，而取决于运营企业是否足额储备、能否按面值兑付。**信任风险因此集中在运营企业身上。** 这和银行存款、支付宝余额完全一样：用户之间转账，转移的是对银行或平台的债权，底层的央行货币并没有动。

**信息系统能保证系统内记录的转移；记录能否兑换成真钱，取决于运营方和监管。** 跨系统转移则需要运营方配合，并与对端系统对接、对账。电信已经证明，统一标准 + 互联协议 + 清算中心，可以让全球数千家运营商互通，而不需要共享账本。代价是接入门槛高、协议谈判成本高。

**区块链能保证一条链内记录的转移，同样保证不了记录背后的资金。** 只有链上原生资产（如比特币）是例外：代币本身就是资产，不存在链下对应关系。稳定币、代币化存款等链上法币资产，本质都是发行方的负债，链只负责记账。区块链相对信息系统的真实优势在于：同一条链上，任何有钱包的人都能接收和转出这条记录，不需要逐家对接。但除了链下对应这个根本限制，还有四个边界：

- **跨链不自由**：资产离开本链要经过跨链桥，而桥是最大的安全风险点；链越多，流动性越分散
- **可以被冻结**：如上所述，受监管稳定币的流通随时可能被发行方中止
- **入金和出金依赖银行**：链上资产换回本地法币，仍要经过传统银行体系和外汇管制
- **技术最终性不等于法律最终性**：链上转账不可撤销，但法院仍可判令返还；持有私钥不自动等于法律上的所有权

| 问题 | 信息系统（数据库 + 清算协议） | 区块链 |
| --- | --- | --- |
| 互不信任的多方共同记账 | 靠受监管的中心运营方 | 靠共识 + 密码学，有条件成立 |
| 记录与真实资金是否对应 | 取决于运营方 + 审计 + 监管 | 同样取决于发行方 + 审计 + 监管 |
| 系统内记录（债权）转移 | 能保证 | 能保证 |
| 跨系统转移 | 靠标准 + 互联协议 + 清算中心 | 同一条链内免对接；跨链靠桥，风险高 |
| 信任风险所在 | 运营方 | 发行方与链的运营企业 |
| 法律可执行性 | 强 | 取决于发行方和监管，而非链本身 |
| 监管介入后的作用 | 不变 | 从“替代信任”变为“共享事实、降低对账成本” |

**结论：单靠区块链，只能保证业务名义上的信任。** 多方信任的风险在区块链的设计和建设企业；资产流通的风险在链上信息与真实资产的对应，同样取决于运营企业。

区块链并没有消除信任风险，而是把它从业务各方之间，转移并集中到了区块链的设计和运营企业身上。单靠区块链，不能保证实际的多方信任和资产流通。

因此，要让区块链方案获得实际的信任，必须对这些企业施加与银行、清算所同等的技术、监管和治理约束。这也是区块链只能做“锚点”、不能独自承担信任的原因。

## 区块链的优势来自三项自动化预设能力

区块链的优势，主要依赖于它以自动化方式预设的三项能力。在监管介入的情况下，分布式数据库系统同样可以通过自动化协议预设类似的能力；与之相比，区块链的竞争力被严重削弱。

### 三项预设能力，分布式数据库都能实现

区块链本质上是一套预设方案：它把开放互操作、透明可审计、多方共同写入三项能力，用自动化的方式固定在协议里。只要确定了相应的协议并作为准入要求，分布式数据库同样可以实现。

| 预设能力 | 区块链的自动化实现 | 分布式数据库的对应实现 |
| --- | --- | --- |
| 开放互操作 | 统一的地址和代币标准，任何钱包都能接入 | 统一 API 与报文标准（如 ISO 20022）+ 准入规则。巴西 Pix、印度 UPI、开放银行、电信互联都是先例 |
| 透明与实时可审计 | 全网公开账本 | 监管直连的只读节点 + 防篡改账本表 + 可验证日志 + 定期向外部公布账本哈希 |
| 多方共同写入，任何一方不能单独控制 | 共识算法写死在链上 | 拜占庭容错复制协议（如 PBFT、HotStuff，早于区块链）+ 每笔写入须 k/N 家机构门限签名 + 监管者持有见证副本自动比对 + 可信执行环境 |

第三项最关键，也最常被认为是区块链独有的。事实上，拜占庭容错协议是分布式系统的通用技术，并非区块链发明。监管机构完全可以把它写成准入条件，例如：结算账本须由至少 N 家独立机构共同维护，任何写入须经 k/N 签名，监管者实时持有完整副本。银行业的双人复核、美国证券业的综合审计追踪（CAT），本来就是监管强制要求的自动化控制。

这种方式需要满足两个前提：

- **独立的运营主体是前提**：如果所有节点都由同一家企业控制，再好的自动化协议也没有意义。这一点区块链和数据库完全一样，都归结为治理安排
- **代价只应出现在结算层**：拜占庭容错要求至少 3f+1 个节点才能容忍 f 个作恶节点，延迟和成本较高。因此只用于结算层，业务层仍交给普通分布式数据库

做到这一步，一个由多家受监管机构共同维护、运行拜占庭容错协议的数据库，在能力上与许可链已无本质区别。两者的差别只剩包装：区块链把三项能力与代币、公开地址、加密经济机制预先捆绑在一起；数据库方案可以只取所需的那几项。

### 监管介入后，区块链的竞争力被严重削弱

| 维度 | 区块链方案 | 分布式数据库 + 自动化协议 |
| --- | --- | --- |
| 信任的最终来源 | 发行方、运营企业与监管 | 运营方、参与机构与监管 |
| 开放互操作 | 预设实现 | 协议 + 准入规则实现 |
| 透明与实时可审计 | 默认全网公开，与隐私要求冲突 | 监管直连、分级开放，更符合隐私要求 |
| 多方共同写入 | 预设实现 | 拜占庭容错协议 + 门限签名 + 监管准入实现 |
| 监管复杂度 | 高：责任主体多且跨法域，代码即规则，资产可流入任意钱包和协议 | 低：责任主体明确，现有监管框架成熟 |
| 扩展与迭代 | 三项能力捆绑，紧耦合，扩展难 | 三项能力分开定义，各自独立演进 |
| 剩余的独特优势 | 无需任何主导方即可跨法域组网，但受监管稳定币恰恰放弃了这一点 | — |

在没有监管的开放环境里，预设能力是区块链的优势：参与者不需要谈判和准入，就能获得一套现成的信任、互操作和透明规则。监管介入后，情况反转：

1. **预设的信任让位于监管**：发行方必须保留冻结能力，验证者向受监管机构收拢，最终信任来源与数据库方案相同
2. **预设的能力不再独有**：三项能力都可以由分布式数据库通过协议实现，并作为监管准入强制执行
3. **预设的代价依然存在**：三项能力捆绑带来的紧耦合、扩展难，以及更高的监管复杂度，并没有因监管而消失

这正好回到本文开头的问题：跨境支付企业面临的扩展性困境，根源就在于区块链把这些能力预设并捆绑在一起。

因此，对监管者而言，合理的思路是**能力导向、技术中立**：要求的是开放互操作、透明可审计、单方无法作恶这些能力，而不必指定区块链这一种技术。区块链只是满足这些要求的一种预设实现，而且在受监管环境中，往往不是成本最低、最灵活的那一种。

## 三条演进路线

三条路线的性质很不一样：第一条是退出区块链，第二条在技术上属于类别错配，第三条才是行业正在走的路。

### 路线一：放弃窄场景，用分布式数据库重构平台

**可行性：技术上完全可行，业务上取决于定位。**

分布式数据库（如 Spanner、CockroachDB、TiDB、OceanBase）已经非常成熟。全球最大的支付系统，大多跑在这类中心化、分布式的数据架构上。

优势：

- 性能高出几个数量级：万级到十万级 TPS，毫秒级延迟，强一致事务
- 功能扩展快：改表结构、加服务、拆微服务都是成熟工程，人才供给充足
- 合规友好：数据可修改、可删除，隐私控制简单，审计路径清晰
- 成本可预测：没有 gas 费，不受链上拥堵影响

劣势：

- **信任模型变了**：分布式数据库是“物理分布、逻辑集中”，节点之间默认互信，只防崩溃不防作恶。账本的可信度完全来自运营方
- **稳定币会退化**：私有数据库里的“稳定币”本质上就是电子货币或预付余额，失去外部生态中的流通性
- **跨机构互联要重新谈**：每接一家合作方都要双边对接和对账，又回到代理行模式
- 迁移成本高：链上资产要赎回或映射，用户和合作伙伴都要迁移

适用对象：本质上是汇款或收单公司、链只用于内部记账的企业。对它们来说，回归数据库是合理的“去伪存真”。

需要注意：上述“信任模型变了”和“稳定币会退化”两项劣势，针对的是普通分布式数据库。如果按上一章所述，加入多方共同写入的自动化协议并作为监管准入，这两项劣势可以基本消除。在受监管场景中，这条路线的适用范围也就扩大到稳定币发行方和支付网络。

### 路线二：用分布式文件系统替换区块链

**可行性：作为替代方案基本不可行；作为补充组件有价值。**

分布式文件系统（IPFS、HDFS、Ceph、Filecoin、Arweave 等）解决的是“大文件怎么存、怎么取”。支付系统的核心问题则是“状态怎么变、谁先谁后、如何防止双花”。两者不在同一个层面。

- **没有全局排序和共识**：文件系统不判断两笔转账谁先发生，无法防止双花
- **没有状态机**：没有余额、账户、交易校验的概念。这些逻辑都要在上层重新造，最后还是造出一个数据库或一条链
- **内容寻址不等于账本完整**：IPFS 只保证文件内容没被改过，不保证交易记录完整、有序、不被删除
- 隐私风险更高：公开网络上的文件系统不适合存放 KYC 资料或交易明细

它在架构里的正确位置：存放发票、贸易单据、合同、审计报告等大文件，链上只存哈希作为存证；作为数据可用性（DA）层的一部分；归档历史数据。它不应该作为“替换区块链”的方案，而是路线三里的数据层组件。

### 路线三：最小化区块链基础设施，增加多功能多层能力

**可行性：最高，也是行业的主流方向（模块化架构）。**

思路是把区块链收缩到它不可替代的部分——结算、最终性、资产所有权证明——其余能力分层外移。

优势：

- 保留区块链的核心价值（多方信任、资产流通），同时把性能瓶颈移出去
- 各层可以独立升级：换执行环境、加隐私模块、接新的合规规则，都不用动底层
- 渐进迁移：现有链上资产不需要推倒重来
- 可按地区差异化：某些市场用许可链或私有执行层满足本地监管，结算统一回到主层

劣势与风险：

- **系统复杂度大幅上升**：层数越多，故障点越多，跨层一致性和安全审计都更难
- **跨链桥和跨层通信是最大的安全风险**：历史上金额最大的加密盗窃事件多数发生在桥上
- **信任假设碎片化**：排序器、DA、预言机、桥各有信任前提，整体安全性取决于最弱的一层
- **流动性分散**：多条执行链或应用链会把稳定币流动性拆成很多份
- 对团队要求高：既要懂区块链，也要懂传统金融系统架构

## 三条路线对比

路线一换来性能，在受监管场景下加上自动化协议还能补回多方信任；路线二不成立；路线三保留区块链的名义价值，代价是复杂度。

| 维度 | 路线一：分布式数据库 | 路线二：分布式文件系统 | 路线三：最小链 + 多层 |
| --- | --- | --- | --- |
| 技术可行性 | 高 | 低（类别错配） | 高 |
| 性能扩展 | 最强 | 不适用 | 强 |
| 功能迭代速度 | 最快 | 不适用 | 快（各层独立升级） |
| 多方信任与资产流通 | 普通数据库丧失；加自动化多方写入协议 + 监管准入可实现 | 丧失 | 名义上保留，实际取决于运营企业 |
| 合规与隐私 | 最容易 | 较差 | 可设计，但复杂 |
| 监管复杂度 | 低 | — | 高 |
| 迁移成本 | 高（推倒重来） | — | 中（渐进迁移） |
| 系统复杂度 | 低到中 | — | 高 |
| 主要风险 | 未加协议时失去差异化 | 方案本身不成立 | 桥和跨层安全、风险集中于运营企业 |
| 适合谁 | 链只用于内部记账的企业；受监管场景下，加协议后也适合发行方和支付网络 | 仅作单据存证、归档组件 | 无监管或跨法域开放场景、依赖链上流动性的企业 |

现实中最可能胜出的不是三选一，而是“路线三为骨架、路线一为躯干、路线二为组件”的混合架构。

## 推荐架构：分层结构

链只留在最底层做结算和证明；业务放在上层的数据库里；中间各层按需增加、独立升级。

[![区块链只做最底层的结算，其余能力分层外移：应用层、业务服务层（分布式数据库 + 微服务）为业务的容器；合规与身份、执行、数据、互操作层按需增加；结算层（最小化区块链）为信任的锚点](/images/articles/trust-anchor-architecture-zh.png)](/images/articles/trust-anchor-architecture-zh.png)

自上而下读：用户和合作方通过应用层发起业务，业务服务层在数据库里实时记账，经过合规筛查后由执行层批量处理，最终在结算层完成最终结算。结算层变化最少，应用层和业务服务层迭代最快。

这个结构把三条路线各自的长处组合起来：路线三提供骨架（最小化的结算层），路线一提供躯干（分布式数据库承载业务），路线二提供组件（文件存储放在数据层）。

## 判断标准与迁移路径

每个功能放在哪一层，只问一个问题：**这个功能需要互不信任的多方共同确认吗？** 需要，就上链；不需要，就放数据库。

按这个标准，常见功能的归属如下：

| 功能 | 需要多方共同确认？ | 放在哪里 |
| --- | --- | --- |
| 稳定币发行与销毁 | 是 | 结算层（链上） |
| 机构间最终结算 | 是 | 结算层（链上） |
| 储备证明 | 是 | 结算层（链上） |
| 单据存证 | 是，但只需哈希 | 哈希上链，原件存分布式存储 |
| 订单、路由、汇率报价 | 否 | 业务服务层（数据库） |
| 风控与反洗钱筛查 | 否 | 合规层 + 数据库 |
| 客户资料与 KYC 档案 | 否，且必须可删除 | 数据库（绝不上链） |
| 内部对账与报表 | 否 | 数据库 |

对已经把业务建在链上的企业，建议按四步渐进迁移：

1. **盘点功能**：用上表的标准把现有链上功能逐项归类，找出“不需要多方确认却放在链上”的部分
2. **业务先下链**：把订单、路由、风控、对账迁入分布式数据库，链上只保留结算与资产
3. **改为批量结算**：高频交易在数据库中实时记账，按周期做净额结算后提交到链上
4. **按需加层**：只在有明确需求时增加执行层、隐私模块或跨链通道，每加一层都要单独评估其信任假设和安全风险

## 历史类比与行业动向

“实时记账 + 定期净额结算”不是新发明，电信和银行清算用了几十年。新一代支付专用链正在向同一个模式靠拢。

**电信的做法。** 全球漫游中，每一通电话、每一次数据使用，都先在各运营商自己的计费系统里实时记录。运营商之间并不逐笔结算，而是通过清算中心定期交换话单、核对差异，再做净额结算。业务在各自的容器里跑，只有结算需要多方共同确认。

**银行清算的做法。** 银行内部的核心系统实时记账，跨行资金则通过实时全额结算（RTGS）或净额清算系统完成最终结算。清算系统极少改变，而银行的产品和业务系统一直在迭代。这正是“锚点稳定、容器灵活”。

区块链在这个模式里的角色，是把“清算中心”变成一个多方共同维护、不属于任何一方的结算层。它替代的是清算中心，而不是各家的计费系统和核心系统。

**行业动向。** 新一代支付专用链都在收窄链的职责、加强周边能力：

- [Stripe 孵化的 Tempo](https://fortune.com/2026/03/18/stripe-tempo-paradigm-mpp-ai-payments-protocol/) 于 2026 年 3 月上线主网。[Stripe 文档](https://docs.stripe.com/stablecoins/ecosystem/tempo)将其定位为稳定币支付专用链，内置隐私、账户级控制和对账能力
- [Circle 的 Arc](https://www.theblock.co/news/ecosystems/2026-09-16-circle-launches-arc-mainnet-blackrock-and-visa-among-validators-mints-10-billion-arc-tokens-415250) 于 2026 年 9 月 16 日上线公开主网，用 USDC 支付手续费，并把支付网络和外汇结算服务集成进链
- 值得注意的是，[Arc 的区块由一组固定的受监管金融机构生产](https://thedefiant.io/news/blockchains/circle-launches-arc-mainnet-with-blackrock-dtcc-and-visa-producing-blocks)，而不是开放的验证者市场。信任被锚定在少数可问责的参与方身上，这与传统清算体系的治理结构非常接近

这些链走的都是同一个方向：链只管结算和信任，合规、隐私、对账等能力以模块形式提供。

## 结论

跨境支付和稳定币平台的扩展性问题，根源不在区块链技术本身，而在于把它用错了地方：让一个为多方信任而设计的系统，去承担高频、复杂、需要隐私的业务。

更进一步说，单靠区块链并不能保证实际的多方信任和资产流通。它保证的只是业务名义上的信任，真正的风险反而集中到了区块链的设计和运营企业。

三条路线中，用分布式文件系统替换区块链在技术上不成立。在没有监管的开放场景，最小化区块链、分层扩展仍有优势。在监管介入的场景，分布式数据库加自动化协议可以实现区块链的三项预设能力，而且监管复杂度更低、扩展更灵活，竞争力明显超过区块链方案。

给架构师和产品负责人的一句话：**让链做锚点，让数据库做容器。** 把两者分开，各自都能做好自己的事。
